2 Cài đặt web app chính

2.1. Tải mã nguồn & cài dependency

git clone https://github.com/dongphuongman/Post-Automation.git
cd Post-Automation
npm install

2.2. Tạo file cấu hình môi trường

Sao chép file mẫu .env.example thành .env.local:

cp .env.example .env.local

Sau đó mở .env.local và điền các giá trị (xem chi tiết ở Mục 4).

2.3. Chạy ứng dụng

npm run dev        # Chạy chế độ dev tại http://localhost:3000
npm run build      # Build bản production
npm run start      # Chạy bản production đã build
npm run lint       # Kiểm tra lint

Mở trình duyệt tại http://localhost:3000 để bắt đầu.

3 Khởi tạo Database

Không cần migration thủ công Database tự khởi tạo ở lần gọi API đầu tiên (mở trang chính hoặc đăng nhập).
  • Hàm initDb() tự động tạo 7 bảng: sources, articles, posts, facebook_pages, facebook_groups, app_config (lưu secret mã hóa), users.
  • initDb() cũng seed sẵn một tài khoản admin (xem Mục 3.1).
  • Hàm seedDb() tự động thêm sẵn 6 nguồn RSS mặc định (TechCrunch, NFX, Indie Hackers, a16z, Crunchbase News, TechStartups).

Bạn chỉ cần đảm bảo biến POSTGRES_URL trong .env.local trỏ đúng tới database Neon còn hoạt động.

Lấy connection string Đăng nhập Neon Console → tạo project → copy chuỗi kết nối dạng postgresql://user:password@host/dbname vào biến POSTGRES_URL.

3.1. Đăng nhập lần đầu & tài khoản admin

Hệ thống có xác thực đa người dùng. Tài khoản admin được seed tự động:

Email:    admin@local
Password: admin123
  • ⚠️ Đổi mật khẩu ngay sau khi đăng nhập tại trang /profile.
  • Tạo thêm người dùng, phân quyền (admin / user) tại /manage/users (chỉ admin).
  • Mỗi người dùng chỉ thấy dữ liệu của mình (owner_id); admin thấy tất cả.
Cần khóa mã hóa Đăng nhập yêu cầu biến APP_ENCRYPTION_KEY đã được đặt (dùng để ký session) — xem Mục 4.

4 Cấu hình biến môi trường

4.1. Bắt buộc

# Database — Neon Postgres (bắt buộc)
POSTGRES_URL=postgresql://user:password@host/dbname

# Khóa mã hóa (BẮT BUỘC) — mã hóa secret trong DB (AES-256-GCM) + ký session đăng nhập
# Sinh 1 lần rồi GIỮ CỐ ĐỊNH:  openssl rand -hex 32
APP_ENCRYPTION_KEY=

# Nhà cung cấp LLM: "openai" (mặc định) hoặc "anthropic"
LLM_PROVIDER=openai

# Cấu hình LLM (bắt buộc để viết bài — có thể đặt ở /manage/settings thay vì đây)
LLM_BASE_URL=https://api.openai.com/v1     # Bỏ trống nếu dùng Anthropic
LLM_API_KEY=sk-...
LLM_MODEL=gpt-4o
Mẹo Phần lớn secret (LLM, image, Facebook, scraping) có thể cấu hình ngay trong giao diện /manage/settings — được lưu mã hóa trong DB (bảng app_config). Khi đó .env chỉ cần POSTGRES_URL và APP_ENCRYPTION_KEY; các biến còn lại chỉ là phương án dự phòng.

4.2. Tùy chọn

# Sinh ảnh minh họa — mặc định dùng LLM_API_KEY nếu không set riêng
# IMAGE_BASE_URL=https://api.openai.com/v1
# IMAGE_API_KEY=sk-...
# IMAGE_MODEL=dall-e-3

# TTS lồng tiếng cho video Reels (hiện chỉ hỗ trợ OpenAI)

# Gemini — dự phòng khi LLM chính lỗi
# GEMINI_API_KEY=
# GEMINI_MODEL=gemini-2.0-flash

# Thu thập tin từ mạng xã hội (X/Twitter, Instagram)
RAPID_API_KEY=
BRAVE_API_KEY=

# Đăng Facebook (Graph API v21.0)
FACEBOOK_PAGE_ID=
FACEBOOK_ACCESS_TOKEN=
FACEBOOK_USER_TOKEN=

6 Bot đăng Facebook Groups (tùy chọn)

Bot là một tiến trình daemon chạy nền dùng Playwright để đăng bài vào Facebook Groups dưới danh nghĩa Page, đồng thời render & đăng video Reels. Nó poll database mỗi 60 giây, nhặt các bài theo trạng thái trong hàng đợi.

cd bot
npm install
npm run install-browser      # Cài trình duyệt Chromium cho Playwright

Bot dùng chung database với web app — chấp nhận DATABASE_URL hoặc POSTGRES_URL (đặt trong file .env của thư mục bot/ hoặc biến môi trường hệ thống — bot nạp qua dotenv). Bot dùng chung APP_ENCRYPTION_KEY để giải mã cookie/token Page đã lưu, nên key này phải giống hệt web app.

Đăng nhập Facebook (chạy một lần trước khi bot làm việc)

npm run login        # Mở Chromium (không headless) → tự đăng nhập Facebook thủ công

Cửa sổ Chromium mở ra profile cố định tại bot/fb-profile/. Đăng nhập Facebook (qua mọi bước xác minh), rồi đóng cửa sổ — phiên đăng nhập được lưu lại để bot chạy dưới danh nghĩa tài khoản đó.

Lưu ý Không chạy login khi bot đang chạy: cả hai dùng chung một profile.

Cơ chế hàng đợi

Web app đặt bài sang trạng thái ready_for_<đích> (kèm scheduled_time), bot nhặt, chuyển <đích>_posting → posted (hoặc groups_posted); nếu lỗi / không xác nhận đăng được sẽ trả về ready_* để thử lại. Các đích: page, groups, profile (Facebook cá nhân), x, threads, instagram. Threads đăng qua Graph API (không mở trình duyệt); X / Instagram / cá nhân mở phiên Chromium ephemeral nạp cookie riêng của chủ bài (kết nối ở /manage/social & /manage/account). Video Reels đi theo cột video_status: pending → completed.

Các lệnh có sẵn

LệnhChức năng
npm run postChạy bot daemon (node post-groups.js) — loop mỗi 60s
npm run loginĐăng nhập Facebook thủ công (lưu vào bot/fb-profile/)
npm run check-dbKiểm tra 5 bài đăng gần nhất trong DB
npm run fix-dbSửa/đồng bộ schema DB
npm run flushXóa dữ liệu (dùng thận trọng)

Sau khi chạy npm run dev và mở http://localhost:3000, đăng nhập bằng admin@local / admin123 (đổi mật khẩu ngay ở /profile), rồi làm theo 3 bước:

1
Thu thập tin
Crawl tin tức từ RSS / Brave Search / RapidAPI theo nguồn.
2
Chọn & Viết bài
AI viết bài theo giọng văn (POV / News), tự sinh ảnh minh họa.
3
Duyệt & Đăng
Đăng Facebook Page/Group/Reels/cá nhân + X/Threads/Instagram (ngay hoặc hẹn lịch), kèm video Reels. Ảnh AI lỗi có thể bấm 🔄 Tạo lại ảnh.
Thu thập → Viết bài AI → Render video → Đăng Facebook

9 Bảo mật

Hệ thống có sẵn nhiều lớp bảo vệ; hầu hết bật tự động, chỉ cần đặt APP_ENCRYPTION_KEY đúng và giữ cố định.

9.1. Xác thực & phiên đăng nhập

  • Mật khẩu băm bằng scrypt (salt riêng, so sánh timingSafeEqual).
  • Phiên là token ký HMAC trong cookie mkt_session — HttpOnly, SameSite=Lax, thêm Secure khi chạy production, hạn 7 ngày.
  • Thu hồi phiên: khi đổi mật khẩu ở /profile (hoặc admin đổi mật khẩu một user ở /manage/users), mọi phiên cũ của tài khoản đó bị vô hiệu ngay; người vừa đổi được cấp cookie mới nên không bị đăng xuất.

9.2. Mã hóa secret

Token/cookie Facebook Page, cookie FB cá nhân (facebook_accounts), cookie/token X·Threads·Instagram (social_accounts) và secret trong app_config đều mã hóa AES-256-GCM bằng APP_ENCRYPTION_KEY. API không bao giờ trả secret thô — chỉ trả cờ has_token/has_cookies/name.

9.3. Middleware: security headers & CSRF

Mọi response đi qua src/middleware.ts đều gắn header bảo mật, và mọi request ghi (POST/PATCH/DELETE/PUT) tới /api/* bị kiểm tra CSRF — header Origin phải khớp Host, không khớp trả 403.

HeaderGiá trị / tác dụng
X-Frame-OptionsDENY — chống clickjacking
X-Content-Type-Optionsnosniff
Referrer-Policystrict-origin-when-cross-origin
Permissions-Policytắt camera/microphone/geolocation
Strict-Transport-SecurityHSTS 2 năm, includeSubDomains
Content-Security-PolicyCSP nới lỏng đủ cho Next.js; cho phép Google Fonts (fonts.googleapis.com / fonts.gstatic.com)
Lưu ý CSP Nếu bạn nạp thêm asset từ domain ngoài (script/style/font/ảnh CDN mới), phải whitelist domain đó trong Content-Security-Policy ở src/middleware.ts, nếu không trình duyệt sẽ chặn.

9.4. Rate limit

EndpointGiới hạnKhóa theo
/api/auth/login5 lần / phút → 429IP (chống brute-force)
/api/research10 lần / phút → 429người dùng (session)
/api/write10 lần / phút → 429người dùng (session)

Rate limit lưu trong bộ nhớ tiến trình (đủ cho self-host 1 tiến trình); reset khi khởi động lại app.

9.5. Phân tách dữ liệu theo người dùng

User thường chỉ thấy dữ liệu của chính mình (articles, posts, pages, groups, sources, dashboard, stats) nhờ lọc theo owner_id; tài khoản admin thấy tất cả. Trang /manage/settings và /manage/users chỉ admin truy cập được.

Quan trọng APP_ENCRYPTION_KEY phải sinh một lần và giữ cố định vĩnh viễn. Đổi key sẽ khiến toàn bộ secret đã lưu và session hiện tại không giải mã được.
